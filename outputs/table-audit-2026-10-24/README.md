# 当前牌桌与鱿鱼结算体验审查

日期：2026-10-24。基线：`b573535`。本轮只取证和提出建议，未修改业务代码，未发布。

## 结论

建议优先处理以下两项。第一项有明确的文字遮挡；第二项影响本人筹码的快速识别。没有发现值得追加为第三项的结算问题。

### 1. 375 竖屏右下玩家的下注额被座位卡遮住

- **证据**：[03 稳定状态截图](03-375-stable-bets.jpg)。海棠座位上方仅露出下注筹码的小边缘，无法读出其下注 20。经正常房间状态广播后仍存在，不是切换瞬间。
- **测量**：CSS 视口 375×812。座位卡 x=264.97、y=345.25、宽92、高38；下注标签 x=282.33、y=339.69、宽40.20、高18。二者重叠约40.20×12.44像素。
- **用户影响**：无法直接判断右下玩家投入多少，需要额外查记录，影响下注归属和金额识别。
- **最小建议**：调整该座位下注标签的位置，避开座位卡，同时保留清晰的座位归属；不应简单把所有标签盖到头像或公共牌之上。
- **验收**：同一六人、本人行动状态下，375竖屏五个对手的下注金额均完整可读；桌面、320竖屏及568横屏的归属关系和公共牌可见性不受影响。
- **判断边界**：这是当前实际画面的独立发现，尚未追溯引入版本，不能归因于本次创建/加入页修改；也不以此前已记录的320拥挤豁免替代本问题。

### 2. 本人冻结筹码过小，可用与冻结金额不易快速区分

- **证据**：[02 375本人行动](02-375-own-turn.jpg)、[04 320本人行动](04-320-own-turn.jpg)、[05 横屏本人行动](05-568-own-turn.jpg)。本人金额旁的“冻250”计算字号为9px；主金额没有“可用”提示。
- **用户影响**：鱿鱼模式需要持续区分可下注筹码与冻结资产，当前本人信息需要细看才能分清。
- **最小建议**：仅加强本人区域，明确展示“可用1750 / 冻结250”等含义，冻结金额提高至约11–12px并保持足够对比；复用现有服务端金额，不调整计算规则。
- **验收**：320、375和568横屏在100%显示比例下可直接辨认本人可用及冻结金额；余额仍与原始状态一致，主要行动按钮和手牌不因新增文字受遮挡。
- **判断边界**：属于当前可读性改进，不是余额错误或经验证的无障碍合规结论。

- 使用现有 `test/squid-ui-fixture.js` 启动单个隔离本地房间，五个虚拟对手，加上实际浏览器中的房主；不是线上真实业务数据。
- 创建鱿鱼房间，买入2000、盲注10/20、支付额50。六人每人初始冻结250。发牌随机，行动与获胜顺序受控：高进、陈小刀、阿星、龙五、审视房主依次取得五个标记。
- 使用实际服务端行动和房主设置入口，没有通过浏览器改写应用状态。为稳定取证，现有脚本把行动时限设为600秒并暂停自动下一手；不代表生产默认时限。
- 图片逐张保存并打开核对，包括结算后的左张公开状态；没有空白图或过渡帧。03在一次正常状态更新后再次确认。

- 仅桌面浏览器模拟CSS视口；未验证真机键盘、实际设备旋转、触控手感或动画性能。未扩大到全套自动测试。既有320拥挤限制不列为新增缺陷。
