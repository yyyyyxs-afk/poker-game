## 键盘交互返工

桌面浏览器复现发现，设置和复盘打开后按 Tab 可以移到牌桌控件；设置和复盘也没有自己的 Escape 关闭处理。玩法说明已有 Escape 关闭和焦点返回，本轮保留该交互并加入同一焦点边界管理。

- 设置、复盘和玩法说明都把 Tab 与 Shift+Tab 限制在当前最上层可见对话框。按 Escape 只关闭最上层对话框；关闭后优先回到打开入口。入口因牌局状态更新而隐藏时，焦点回到可见菜单按钮。
- 设置弹窗补齐对话框语义；打开后焦点进入起始筹码输入框，取消、保存成功及 Escape 关闭后返回房管设置按钮（若仍可见）。
- 复盘在下一局状态到达时自动收起，焦点回到本局详情按钮；若当前牌局没有可回看的结果，则回到可见菜单按钮。
- Esc 只有在对话框打开时才由弹窗管理接管；普通状态下聊天输入保持焦点。加注输入框原有 Enter 监听未改动，本轮未专门重测加注流程。

本地独立端口 3456 的 Chromium 实测。键盘和触屏关闭测试通过页面内临时结算夹具打开正式复盘界面，牌桌仍由本地测试服务器提供；视口尺寸以页面 `innerWidth`、`innerHeight` 读数为准。

## 结算到账金额修正

复现发现：旧复盘模板把整池金额写在每位赢家的行内，100 筹码由两位赢家平分时，会显示两人各赢 100。服务端的筹码发放函数原先只改玩家筹码，不把每池个人到账写入结算结果。

- 服务端现在由同一个 `awardPot` 计算并发放筹码，同时把各赢家实际到账金额写入该池的 `winners[].amountWon`。弃牌直接获胜也经过该发放函数；庄家左侧优先取得奇数零头的原规则未变。
- 新复盘逐人显示“分得 N 筹码”；多人主池横幅显示“赢家合计分得 +N”。缺少新字段的旧多人复盘只显示“共享底池（个人分配未记录）”，不再将整池金额显示成每人所得。旧单赢家记录仍可准确显示整池金额。
- 筹码到账与净变化分开显示：个人底池行显示本池实际到账；“本局净盈亏”继续显示本手结束筹码减去起手筹码，扣除了该玩家本手投入。

确定性规则回归：

| 场景 | 验证结果 |
|---|---|
| 100 筹码、两位赢家 | `amountWon` 为 50 / 50，实发筹码也为 50 / 50。 |
| 101 筹码、两位赢家 | 庄家座位 0 时，其左侧座位 1 得 51，座位 0 得 50；符合原零头顺序。 |
| 多层边池 | 池额为 400 / 300 / 200；到账分别为 133/134/133、150/150、100/100，每池到账合计等于该池金额。 |
| 弃牌单赢 | 100 筹码底池由一人全得 100；其净盈亏为 +60，弃牌者为 −60，显示口径彼此独立。 |

本地 Chromium 复盘页在 1366×768 下用页面内的确定性结算夹具实测：100 筹码双人平分横幅显示“赢家合计分得 +100”，两行分别显示“分得 50 筹码”，净盈亏显示 +30 / −30。旧多人记录显示共享池且注明“个人分配未记录”；旧单赢家记录显示其全得金额。截图 `after-payout-split-1366x768.jpg` 为实际复盘界面 JPEG，尺寸核验为 1366×768。
