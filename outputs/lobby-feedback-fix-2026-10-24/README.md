2026-10-24；从`7fa78a9`接续。实现与相关小回归提交：**`e6c23cd`**。本轮不推送、合并或部署。

## 完成的行为

1. **未连接不发业务请求**：大厅显示连接中、失败、断开及恢复状态；昵称、房号和创建设置可填写/保留，可返回。未连接时点击不会进入忙碌态，也不会把创建、查房或加入留在普通离线队列里。恢复只提示主动提交。
2. **只读查询有限等待**：8秒未获有效回执即结束等待，保留资料，明确可手动重查。编辑昵称/房号或离开该流程，会废弃在途查询的本地结果；旧回执不能打开退出的预览或覆盖新流程。
3. **创建/加入未知态**：10秒未获有效回执，或发送中断线/返回其他流程，显示“结果未确认，原操作可能已成功；不会自动重发”。解开编辑锁，但普通创建、加入确认仍被防重提状态阻止。返回大厅、编辑及重连均不解除该状态。
4. **另建必须独立确认**：展开“未确认操作”，勾选“我知道原房可能仍存在，另建会产生不同房间”，再点击“放弃等待，另建新房”。这一步只准备新操作、重新连接；不自动建房。新连接恢复后，仍须主动点击“创建新房间”。此路径只放行另建，不能顺带变成其他加入操作。
5. **旧结果与凭证隔离**：本地请求实例已取消/过期/放弃后，旧回执不再调用成功分支。没有凭证的“成功”回执按未知结果处理。正常成功仍按原来的`saveAuth → enterRoom`路径，不凭状态广播、昵称、公开房号或旧last-room恢复身份。

只新增大厅专用生命周期组件`public/lobby-requests.js`，没有通用全站请求库、请求ID、幂等协议或恢复API。服务端、资金/玩法规则、token校验和已有聊天组件未改。

## 边界与实际影响

- **这不是找回丢失创建token的方案。** 超时后即使服务端可能已建房/加入，也不会仅凭状态广播自动进入或保存猜测凭证；旧回执过期后不再接管本页身份。
- 明确另建会断开当前大厅Socket并重新连接。如果原操作已成功，原房/原席位按服务端已有断线规则处理；新连接没有自动建房。这不是删除原房，也不保证原房一直存在。
- 未知态和草稿只保留在**当前页面**。刷新、关闭后不承诺恢复，也不会因此撤销服务端已发生的原操作；不能把刷新当作安全重试方式。
- 连接检查加`volatile`、限时回执用于避免普通离线缓冲并隔离不确定结果；它不是“消息永不丢失”的保证。网络竞态下仍可能丢请求或回执，因此保留“原操作可能已成功”的未知态，不自动重发。
- 未新增线上身份恢复路径，未改登录/权限。没有操作真实线上网络、用户房间、3000/3477/3478、旧d260、隧道或主目录HANDOVER。
